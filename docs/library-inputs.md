# 显式库文件

前导 filelist（`-p`）中的 `-v path` 将文件声明为库输入。多个不同的库文件即使包含同名 UDP 或模块，也会按输入顺序全部保留，并保留每一条 `-v` 前缀。例如：

```text
-v models/udp_a.v
-v models/udp_b.v
```

生成结果保留这两行，自动收集不会再将它们追加成裸源码。不需要新增命令行参数。库文件可以通过嵌套 `-f` 引入；路径相对所属 filelist 解析，再按输出位置重定位，含空白的库路径加引号。

## 输入角色与定义选择

| 输入 | 处理方式 |
| --- | --- |
| 普通源码路径 | 作为普通编译源码，重复定义仍报错 |
| `-v path` | 保留库角色，模块与 UDP 登记为有序候选，允许不同库有同名候选 |
| `-y dir`、`+libext+` | 继续按模块名与后缀查找库目录中的文件 |

定位先检查普通源码；找不到时使用显式库中最先出现的有效定义，再尝试库目录。后来解析的普通源码定义可以替代此前选中的库候选；两个普通定义仍构成冲突。生成器的候选选择用于依赖收集，实际展开、库优先级与重名诊断由下游编译工具决定。

同一实际文件以相同角色重复输入时只保留第一次的位置和逻辑路径。若同一文件同时以裸路径和 `-v` 输入，工具明确报告角色冲突。包定义仍需要唯一性与声明在使用前的顺序，不因位于 `-v` 文件而忽略重复包错误。

## 依赖与边界

显式库文件仍按前导条目顺序进行文件级预处理与依赖收集：活动分支、include、包引用和外部子模块依赖继续检查，缺失时失败并保留旧清单。两个库都被显式指定时，两者的活动引用均参与检查；工具不实现编译器按单元惰性展开，也不会因为某个同名候选未被选中而跳过它所在文件的其他依赖。

宏状态延续既有前导输入时间线。不同编译器的库文件预处理和编译单元规则可能不同；本工具不模拟所有编译器的宏隔离规则。缓存不保存永久的输入角色；每次构建从当前前导输入重新确定角色，旧普通源码定位提示不能把显式库重新变成普通候选。

库文件选项的依据见 [Icarus 命令文件格式](https://steveicarus.github.io/iverilog/usage/command_files.html)和 [Verilator 参数](https://verilator.org/guide/latest/exe_verilator.html)。保留库选项不保证下游工具对所有重名设计均无警告。
