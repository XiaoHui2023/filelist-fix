# 显式库文件

前导 filelist（`-p`）中的 `-v path` 将文件声明为库输入。多个不同的库文件即使包含同名 UDP 或模块，也会按输入顺序全部保留，并保留每一条 `-v` 前缀。例如：

```text
-v models/udp_a.v
-v models/udp_b.v
```

生成结果保留这两行，自动收集不会再将它们追加成裸源码。不需要新增命令行参数。库文件可以通过嵌套 `-f` 引入；路径相对所属 filelist 解析，再按输出位置重定位，含空白的库路径加引号。

## 输入角色与定义选择

| 输入 | 处理方式 |
| --- | --- |
| 普通源码路径 | 作为普通编译源码，重复定义仍报错 |
| `-v path` | 保留库角色，模块与 UDP 登记为有序候选，允许不同库有同名候选 |
| `-y dir`、`+libext+` | 继续按模块名与后缀查找库目录中的文件 |

定位先检查普通源码；找不到时使用显式库中最先出现的有效定义，再尝试库目录。后来解析的普通源码定义可以替代此前选中的库候选；两个普通定义仍构成冲突。生成器的候选选择用于依赖收集，实际展开、库优先级与重名诊断由下游编译工具决定。

同一实际文件以相同角色重复输入时只保留第一次的位置和逻辑路径。若同一文件同时以裸路径和 `-v` 输入，工具明确报告角色冲突。包定义仍需要唯一性与声明在使用前的顺序，不因位于 `-v` 文件而忽略重复包错误。

## 依赖与边界

显式库文件仍按前导条目顺序进行文件级预处理与依赖收集：活动分支、include、包引用和外部子模块依赖继续检查，缺失时失败并保留旧清单。两个库都被显式指定时，两者的活动引用均参与检查；工具不实现编译器按单元惰性展开，也不会因为某个同名候选未被选中而跳过它所在文件的其他依赖。

宏状态延续既有前导输入时间线。不同编译器的库文件预处理和编译单元规则可能不同；本工具不模拟所有编译器的宏隔离规则。缓存不保存永久的输入角色；每次构建从当前前导输入重新确定角色，旧普通源码定位提示不能把显式库重新变成普通候选。

库文件选项的依据见 [Icarus 命令文件格式](https://steveicarus.github.io/iverilog/usage/command_files.html)和 [Verilator 参数](https://verilator.org/guide/latest/exe_verilator.html)。保留库选项不保证下游工具对所有重名设计均无警告。

## 精简器件库

使用 `--compact-libs` 精简器件库清单。符合条件的器件不再逐文件列出，改为按库整体搜索；输出采用 `-y` 和 `+libext+`：

```sh
filelist-fix -s rtl models -t top -p pre.f -o out.f --compact-libs
```

符合条件的同目录库文件合并为一条目录记录，扩展名统一列出：

```text
+libext+.v
-y models/
rtl/top.sv
```

扩展名紧跟 `+libext+`；多个后缀写成 `+libext+.v+.sv`。工具也接受 `+libext+ .v` 以及 `-y models/ +libext+ .v`，写出时规范为独立行。`-y` 的含空白路径使用引号。相对路径仍以生成清单所在目录为基准。

### 器件库特征

库归属使用“满足任一特征”的规则。`-v` / `-y` 是明确的库声明；自动识别则使用下列源码特征，不要求同时出现：

| 特征 | 常见用途 | 识别边界 |
| --- | --- | --- |
| `celldefine` | 标记单元库模型 | 不要求整个文件的所有单元都在标记中；标记不完整仍可识别为候选，转换时另查 |
| `specify` 或 `specparam` | 路径延迟、时序参数与检查 | 普通 RTL 也能包含，属于模型线索，不是厂商身份证明 |
| `primitive` 声明 | UDP 逻辑或时序真值表 | 用户也可自建 UDP |
| 门与开关原语例化 | `and`、`buf`、`bufif`、MOS、`tran`、`pullup` 等器件级模型 | 普通门级 RTL 也可能命中 |
| 黑盒或库模型属性 | `blackbox`、`black_box`、`syn_black_box`、`whitebox`、`lib_whitebox`、`abc9_box` | 属性说明建模意图，不证明行为或引脚完整 |
| 驱动或电荷强度 | `strong0/1`、`weak0/1`、`pull0/1`、`highz0/1`、`small/medium/large` 的强度声明 | 也可用于普通模型，作为宽松线索 |
| `supply0`、`supply1`、`trireg` | 电源、浮空节点或电荷存储建模 | 也是合法 RTL 语法，作为宽松线索使用 |

普通注释和字符串中的文字不计入特征；`// synthesis syn_black_box`、`// synopsys black_box` 这类明确的综合黑盒注解按模型属性识别。条件分支中的真实特征可以把文件识别为候选，但不据此猜测当前分支或预处理结果。文件内只要有单元涉及上述特征就纳入识别，不要求所有单元都是器件。

目录名、文件前缀、文件大小、叶子模块、`always`、`assign`、`initial` 或参数数量不单独作为识别条件。它们缺乏器件库特异性；完全无上述特征的行为模型可用前导 `-v` / `-y` 明确声明。工具不根据这些线索推断厂商、工艺或时序角。

识别结果与输入改写分开。命中特征的文件即使包含条件编译、include、多个模块或文件级声明，仍记为库候选；不能安全转换时保留原有裸源码或 `-v` 角色。顶层和前导中明确的普通源码保持原输入方式，普通源码的重复定义检查仍执行。

### 转换条件

`-y` 按目录顺序查找“单元名＋扩展名”，不递归读取目录内全部文件。自动转换要求文件只有一个 module/UDP，文件名与单元名一致，且不存在需要原编译顺序的预处理上下文或编译单元外声明。包、接口、程序、编译单元 typedef/函数/import 继续作为普通源码输入。

识别不再要求 `celldefine`，也不要求整个目录都带库特征。目录中的未引用文件不会因 `-y` 自动被解析，因此一个无关、无标记或不能转换的邻居不再否决整个目录；不能转换的选中文件保留自身原输入方式，其余文件可以精简。用户排除的同后缀文件仍阻止新目录引入，避免重新暴露被排除内容。

条件编译、include、宏使用或写入使该文件的转换资格不确定时保留文件输入。任何已选源码中存在可能共享的编译指令状态（例如 `timescale`、`default_nettype`、include 或编译单元外的类型/函数声明）时，自动转换也会保守回退，避免惰性库读取改变其他模块继承的状态。已由用户声明的 `-y` 搜索目录仍保留；这与自动把裸源码或 `-v` 改成目录搜索不同。

输出前按实际选中单元检查目录与后缀顺序，不能改变既有绑定。没有绑定冲突的目录交错不再单独阻止精简。普通源码重复定义和包唯一性在改写前检查；特征识别不赋予忽略冲突的权限。

已有 `-l` 日志分别记录检查文件数、识别库候选数、可转换数、实际精简数及保留原因。识别数量大于精简数量是合法情况：例如包含 100 个单元的合并模型可以被识别为库，却仍需保留一个 `-v all_cells.v`。含空白的保留源码路径也会加引号。

开启后，多个显式 `-y` 目录按声明顺序选择首个可用候选；普通源码仍优先。所有依赖仍先收集和检查，再压缩输出；缺模块、缺包及不可满足顺序时保留旧清单。关闭开关时保留逐文件行为。

源码特征参考 [Yosys 模型属性](https://yosyshq.readthedocs.io/projects/yosys/en/v0.49/yosys_internals/verilog.html)和 [Verilator 语言支持](https://verilator.org/guide/latest/languages.html)；惰性库的宏环境差异见 [Icarus 库预处理规则](https://steveicarus.github.io/iverilog/usage/icarus_verilog_quirks.html#scope-of-macro-defines-doesn-t-extend-into-libraries)。这些规则解释转换边界，不把启发式识别等同于厂商认证。
