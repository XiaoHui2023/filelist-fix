# 定位复用与解析进度

工具按需收集依赖，不预先解析检索目录里的全部源码。定位结果可以提前获取；文件解析和宏状态提交仍按原有输入时间线进行。

```mermaid
flowchart LR
    Name[当前模块] --> Hint[检查有效路径提示]
    Hint --> Filename[会话文件名索引]
    Filename --> Content[按批定位已知引用]
    Content --> Library[库目录候选]
    Library --> Parse[当前文件解析或缓存复用]
    Parse --> State[提交依赖与宏状态]
    State --> Name
```

每一步命中后使用其候选，不必继续后续检索。候选存在不代表定义有效，仍由当前入口宏环境下的解析结果确认。

## 文件名与内容定位

一次构建中，每个检索根的文件名只枚举一次；模块定位和 include 回退共享该索引。新一次构建重新枚举，避免沿用上一轮文件集合。忽略规则由 fd 执行，候选继续应用排除路径、扩展名、大小写和同文件去重规则。

文件名没有命中时，按当前模块和队列里已知的引用预取内容定位结果。每批最多 64 个名字，并限制模式总长度；消费完已缓存的当前名字后才开始下一批。批量结果保存名字与全部候选路径的对应关系，不因同一行或同一文件出现多个声明而丢失映射。

预取不解析文件，不修改宏，不提前报告尚未消费引用的缺失或歧义。源码解析、package 处理与宏状态仍按既有顺序执行。`-y`、`+libext+` 的库检索继续作为源码范围未命中后的候选来源。

## 路径提示

SQLite 保存的文件身份可能是真实路径，用户指定的检索根可能经过目录链接。判断提示是否位于检索范围时，两侧先统一为实际路径；命中后还原到该检索根下的逻辑路径，用于本轮清单输出。

提示仍检查文件存在、排除范围、定义和解析缓存有效性。源文件或入口宏环境变化时，按原规则重新解析。库目录候选不借路径提示跳过重复候选检查。

## 进度与日志

进度条在解析开始前显示当前文件，前导源码也使用相同方式。耗时较长时，当前文件名称持续显示；不再另行打印慢提取提示。

需要排障时使用已有的 `-l run.log`：日志包含定位工具耗时、路径提示命中、缓存命中，以及读取、预处理、语义提取和实例扫描等阶段耗时。阶段存在嵌套，不能直接相加。

普通使用不需要解析计时或阈值参数。原 `--parse-timeout`、`--slow-file-seconds`、`--parse-timings` 已移除，使用这些选项的旧命令需要删去对应选项。

## 失败保护

单源解析保留内置 30 秒协作预算，在阶段边界和扫描检查点检测；它不抢占尚未返回的阻塞操作。单次外部定位保留 120 秒截止，搜索工具失败和超时不能当作“没有定义”。

缺少依赖、候选歧义、解析超时、定位失败或顺序冲突时返回非零；只有完整收集与排序成功才替换已有清单。
